What does HOP mean?

The HOP - hard block override procedure (former data exception) in WN Wealth Navigator - allows a front-facing employee to override a hard block and continue with the suitability test or a trade execution in case of any data issues in the system. 

Examples:

  • Instrument universe status wrongly reflected in WN
  • Intraday movements not yet visible in the portfolio

Additionally, in very dedicated use cases it is used as workaround, where technical implementation is still pending, to permit a trade without waiting for an IT change. These workarounds as well as a description of data issues are listed below (Permitted use cases). 

General RuleIf the HOP is the only option, the intention of the bank is to hard block such a trade (e.g. due to distribution restrictions, failed suitability, advice not permitted etc.) and therefore, overriding shall only be done if permitted (Permitted use cases). In case of active solicitation, advice must always be suitable and the HOP can only be used in case of incorrect data. 

What is the effect of using the HOP?

The HOP neutralizes the respective alert and suggests to the client (e.g. in the PIR) that the trade is suitable according to the bank's framework (including contractual promises). It overrides a hard block in the system and must therefore be carefully used. If this procedure is wrongly used, it results in an unsuitable outcome for the client and exposes the bank to regulatory and litigation risks.

Rollover of an expiring instrument

 

Existing maturing position is still shown in the portfolio and the front-facing employee would like to already recommend a succeeding instrument. This leads to double counting the position and could lead e.g. to SAA or Issuer Concentration alerts. If the issuer and/or underlying instrument class (e.g. equities) remain the same it is considered a rollover. 

  • Specify which instrument will be rolled over and/or matured.
  • Capture the corresponding weight.
    • Provide examples of correct calculation. Such as, “ICR for issuer X is currently at 18%. This transaction is a roll-over of a maturing instrument (same amount) and therefore the ICR remains at 18%”
  • Documentation elements: 
    • Instruments involved
    • ICR/CPR/SAA with maturity/rollover discounted.
    • % that represents the roll-over/re-investment.
    • Final assessment of respective alert (see above)

Incorrect Price/Share class/client flags e.g. US person restriction data/universe status of an instrument or asset class allocation


Any data error that is leading to a wrong result e.g. the universe status is not correct according to the ICO or the instrument is allocated to the wrong asset class etc. If this is leading to calculation or suitability assessment error. If you observe incorrect data, open a ticket via BFS or contact the Instrument Class Owner (e.g. in case of universe status questions). Contacts are listed below. Data errors can also occur when a client status is no longer accurate and not yet changed (e.g. UK RND tax eligibility, US person status etc.). Always ensure that client information is up to date. 

Additional rule for treasury bills (as of 18.03.2026): T-bills issued by Governments are usually within the offered universe but universe status setting may in exceptional cases be delayed. If a T-Bill from the same governmental issuer is already in the offered universe, a separate approval by the ICO is not required but please mention a referential instrument accordingly in the override justification. 


  • Capture reason for incorrect data.
  • Evidence how correct values would not trigger the alert.
  • Always archive the evidence of your clarifications accordingly.
  • Documentation elements: 
    • Instruments involved
    • Correct data and outcome
    • If raised via ticket: ticket-no or if raised to an in-house expert (e.g. instrument class owner): store the e-mail in a CCN/OnDemand and refer it in the comment/CCN, in case of T-bills add referential instrument.

Negative values in SAA (mostly monitoring)

In certain circumstances the current SAA calculation methodology can lead to negative SAA values for the Session or more often in Monitoring (e.g. if “fund splitting” is applied and the fund has hedging or the client has FX/PM forward, Accu/Decu, TARF and similar products). For the FX/PM forward, Accu/Decu etc. the reason lays in the negative market value that is considered (P&L value) in relation to the portfolio gross value. If SAA alert gets triggered due to an asset allocation smaller than a minimum of “0%”, the alert can be closed without contacting the client.


  • In case of negative SAA values:
    • For WN Session (point of sale):
      • Comment that the SAA breach is caused by a negative value (including mentioning the product in question e.g. Fund with respective fund splitting) and close the Session alert using the HOP
    • For Overnight alerts (monitoring – most common use case):
      • Follow the instruction on Strategic Asset Allocation Exposure SAA - Suitability Wiki - Confluence, chapter 4 ("How to resolve this notification).

Toolbox/OTMS orders for consolidated portfolios 901 (same ZR, Service Model and Strategy only)

When a client opts for a consolidated view and monitoring in Wealth Navigator, a "virtual" portfolio (901) is created—provided all underlying portfolios share the same ZR, service model, and investment strategy (see: How to consolidate portfolios - Suitability Wiki - Confluence)

For suitability checks on the consolidated position, always initiate a Wealth Navigator session using portfolio 901. However, when placing orders via Toolbox or OTMS, portfolio 901 is not available; only the individual physical portfolios can be selected. As a result, checks are performed solely on the selected single portfolio, not the full consolidated view.

This is a known system limitation. If an alert is triggered at the individual portfolio level but would not constitute a breach when assessed across the consolidated portfolio 901 (i.e., including all relevant portfolios), the alert may be overridden—subject to documented confirmation that no consolidated threshold is breached.

  • Document the consolidated calculation to verify that the transaction remains within threshold. Example:
    • “Client has consolidated portfolios. Concentration risk alert with 20% triggered for new SP XYZ via Toolbox in portfolio 201, however on consolidated level (portfolio 901) this only represents 5% concentration and is therefore in line. “
  • Documentation elements (based on above): 
    • Instruments involved
    • Alert involved and initial result
    • Final assessment of respective alert

BMO Tax alerts (any) for unsolicited orders (independent of the service model)


This exception guidance does not apply to advised (actively solicited/reverse solicited) orders as the bank should not recommend instruments with a potential negative tax impact.

You do no longer need to use the HOP for BMO tax alerts for unsolicited transactions as a dedicated justification "client informed" is available (see screenshot on the right)



  • Inform the client about the potential negative tax impact and recommend to seek guidance from his/her local tax advisor prior to executing such a trade.
  • Document in the comment field or contact note that you have informed the client about the potential negative tax implications and that you have recommended to seek tax advice.

BMO Tax alerts (UKRND) for solicited orders for UK situs investments made from ‘Post-April 2025 Income Account’ (simple UKRND account segregation) and ‘Pure Capital and Income Account’ or ‘Pure Capital Account’ (comprehensive UKRND account segregation) (all commonly set up as 02.05)

Funds held within the ‘Post-April 2025 Income Account’ (simple UKRND account segregation) and the ‘Pure Capital and Income Account’ or the ‘Pure Capital Account’ (comprehensive UKRND account segregation) (all commonly set up as 02.05) can be remitted free of additional UK taxation (e.g. by investment into UK situs securities), hence advice is permitted (if there is no other critical alert) and the BMO tax hard block in Wealth Navigator can be overruled.

This exception guidance does not apply to UK situs investments made from accounts labelled as ‘Pre-April 2025 Income’ or ‘Former Income’ (commonly set up as 02.03) and as ‘Pre-April 2025 Capital’ or ‘Capital Account’ (commonly set up as 02.01) as these investments are likely regarded as taxable remittance and will trigger UK income tax and/or UK capital gains tax. It is not permitted to provide advice for such transactions or overrule the hard block.

For guidance on tax suitability considerations for former UKRND clients, please refer to the following internal one-pager.

  • Add the following commentary in the comment field:
    • Investment in UK situs security from ‘Pure Capital’ and/or ‘Post-April 2025 Income’  

BMO Tax alerts (UKRND) for solicited orders for UK gilt investments made from ‘Gains Account’ (02.27) within comprehensive UKRND account segregation

The ‘Gains Account’ (02.27) within the comprehensive UKRND account segregation is designed for acquisition of UK situs securities. As all gains held on the ‘Gains Account’ are taxed, the funds can be remitted free of additional UK taxation (e.g. by investment into UK gilts), hence advice is permitted (if there is no other critical alert) and the BMO tax hard block in Wealth Navigator can be overruled.

 This exception guidance does not apply to any other custody accounts than the ‘Gains Account’ (02.27) within the comprehensive UKRND account segregation It is not permitted to provide advice for such transactions or overrule the hard block.

BMO tax alerts for solicited orders for UK-resident corporate account holders:

Given the significant variation in corporate tax regimes and accounting standards, our tax‑suitability guidelines do not extend to corporate account holders. For UK-resident corporate account holders, the UK instrument tax classifications “deeply discounted security” (DDS) and “non-reporting offshore fund” are not relevant, and there is no reason to avoid such instruments. For completeness, other UK instrument tax classifications such as “UK gilt”, “qualifying corporate bond” (QCB) and “reporting offshore fund” are also not relevant and there is no UK tax reason to favour such instruments. For UK situs investments, specific confirmation should be sought from the client or the involved wealth planning advisor that UK situs investments are appropriate from a UK tax perspective.

Hence for UK-resident corporate account holders, advice on DDS and non-reporting offshore funds is permitted (if there is no other critical BMO alert) and the BMO tax hard block in Wealth Navigator can be overruled. This exception guidance does not apply to UK situs investments, unless the UK resident corporate account holder or the involved wealth planning advisor provides explicit confirmation that UK investments are appropriate from a UK tax perspective.

For guidance on tax suitability considerations for former UKRND clients, please refer to the following internal one-pager. 

  • For any queries in relation to investment tax suitability, please contact tax services (taxservices@juliusbaer.com)
  • For any other queries in relation to account segregation, please contact the account segregation competence centre (accountsegregation@juliusbaer.com)
  • For DDS and non-reporting offshore funds, add the following commentary in the comment field: “UK tax suitability rules not applicable to UK corporate account holders”  
  • For UK situs investments, add the following commentary in the comment field: “UK situs investment approved by client or wealth planning advisor”

Digital Asset Trading allowed

Certain countries (currently China and India) ban or restrict the trading of Digital Assets. This includes Direct Digital Assets as instrument (Crypto Token) or Indirect Digital Assets (Structured Products, Exchange Traded Products & Exchange Traded Funds with Digital Assets underlying). The alert is triggered if the account holder is from a banned domicile or if the account holder is domiciled in the BVI. Additional details to the alert can be found here: Digital Assets banned domiciles.

In case the AH is domiciled in the BVI and the BO is not domiciled in China, the alert can be overwritten

  • Documentation elements: 
      • Account Holder/Beneficial Owner’s domicile, stating clearly that the BO is not domiciled in China

Private Label Funds (PLFs) also called Single Investor Funds (SIFs)

PLFs are setup for one specific investor by the "Product Management & Fund Solution" team. 

PLFs are per default setup as Non-Traditional Funds (NTFs) with a Product Risk Rating (PRR) of 7, as a look through to underlying positions is not possible. This situation might trigger multiple alerts (CPR, SAA etc.) in Wealth Navigator, which cannot be resolved and must be overridden.

Overriding alerts on PLFs is restricted for the specific investor, for whom the vehicle was structured incl. related investors (e.g. relatives).

→ See respective guidance for correct handling of the different alerts.

Portfolio under Construction

This use case applies for new portfolios, for which

a) securities and/or cash have not been fully transferred (e.g. only 30% of full investment),

b) the RM receives (or is expecting to receive) portfolio related alerts (such as CPR, SAA, Issuer Concentration) when actively advising to buy a financial instruments (start building up portfolio). 

Background/Issue: Portfolio related alerts are solely considering the current positions (e.g. 30%) and not target allocation (100%) as a reference and hence might be triggered if portfolio is not fully funded.


In order to allow active solicitation for such cases, the portfolio related alerts may be overridden provided that: 

a) agreement at onboarding of transitional period and fact that deviations are not reported to client

    • if phones are not recorded: confirm agreement by sending out a written confirmation ("one-way" - no client signature required) 
    • If phones are recorded: Recording is sufficient 

b) agreed transition period is max. 90 days since money is /assets are first transferred

c) alert documentation with reference to contact note ID (containing written confirmation) or reference to voice recording (date and time)

→ Details can be found in the following front guidance

Multiple Solicitation Types within 1 WN Session

  • If you actively recommend a trade in a session (actively solicited) this solicitation type is the master for all other trades in a session i.e. no advice into a business critical alert.
  • Therefore, the HOP is often the only option available.
  • As advice must be suitable for actively solicited trades, please make a separate advisory session only containing actively solicited trades and then a further session for the remaining trades (e.g. unsolicited trades given by the client or trades which you advice against).
