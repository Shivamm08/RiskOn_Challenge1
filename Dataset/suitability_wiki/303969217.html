Knowledge and Experience (K&E) - general information

https://wiki.juliusbaer.com/spaces/fkh/pages/303969217/Knowledge+and+Experience+K+E+-+general+information

Introduction

The evaluation of the K&E information of each account holder and order giver is a crucial element at the initial point of the suitability framework as K&E is part of suitable and appropriate advice. 

Scope & Applicability

For the scope triggering in CLM, please visit: Service scope for CIP and K&E - CLM User Guide - Confluence. Further detailed information on client constellations can be found below:

1) Client constellations

Individual account: One CIP and one K&E-form for the ZR > Important: If the account holder is a minor, no K&E-form is required for the minor but for the 'holder of parental power'. If you see a 'K&E data required-task' in 'CLM task manager' for the minor account holder, please raise an IT-Ticket to delete this CLM task.

Joint account: One CIP for the ZR. K&E-forms for each account holder on partner level (2 or more - depending on the specific number of partners)

Legal Entity: One CIP for the ZR and each authorized person (authorized signatory, holder of mgmt power, etc.) who acts as order giver needs their own K&E-form on partner level > Important: If you see a 'K&E data required-task' in 'CLM task manager' for the LE-account holder, please raise an IT-Ticket to delete this CLM task.

Life insurance companies, pension solution providers, vested benefit accounts (‘Freizügigkeitskonti’) and a certain types of fiduciary companies: One CIP for the ZR. K&E-form on partner level for the according order giver (order giver is usually not the account holder - therefore no standard requirement to gather a K&E-form for the account holder. However, in certain constellations, the account holder is the order giver - please visit Quick Reference Guide: Client Investment Profile - CIPLIC - Suitability Wiki - Confluence (juliusbaer.com))

Any form of authorized representative (PoA etc.) with empowerment to act as order giver:  K&E-form for this partner. Each partner who acts as order giver mandatorily needs a K&E-form. If an authorized representative does not make use of this empowerment, no K&E-form is necessary

Important to know: In the case of an opening of a new ZR/BR, it might be that the Account Holder already has K&E-data & form in place, because she/he already acts as order giver for other ZR/BR. In this case - if Account Holders already have a valid K&E in place - no new K&E-data/form must be gathered. The requirement for having K&E is already fulfilled. However, you can gather a new K&E if you wish to do so or if the Account Holder wishes to have it updated.

2) Service Models

Within all service models of the bank, the K&E of the account holders and - if given - of additional order givers need to be gathered, except: 

  • EAM end-clients - whereby it is necessary to document the knowledge & experience of the EFA end-client by completing the form 'Knowledge & Experience'

  • Global custody clients

  • Non-Trading-Account (NTA) clients

Important: If you are of the opinion that a 'K&E data required-task' for a partner is wrongly set or there is a missing 'K&E-task', please raise an IT-ticket for CLM. Before raising the ticket, please check all related BRs/ZRs of the partner to check the service model and the according K&E-requirement. If you want to learn more about the 'K&E data required-task' and the task about 'K&E-conflict', please visit: Task Categories - CLM User Guide - Confluence

Assessment logic and framework 

There is a global standard available for each BC and RML. However, the K&E assessment and -form is going through a major change. For the booking centers Luxembourg and Monaco, the new K&E framework has been implemented in September 2023. For the booking centers Switzerland and Guernsey (excl. UK), the new K&E-framework has been implemented in November 2023. For the rest of the world, the assessment and the form did not change yet. Please consult the below-mentioned sites for further information about the new processes. For UK- and Asian-specific requirements, please consult the local intranet sites and guidances.
