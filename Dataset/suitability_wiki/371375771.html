Advisory Session - contact note examples

https://wiki.juliusbaer.com/spaces/fkh/pages/371375771/Advisory+Session+-+contact+note+examples

Important: Remember to write in a way allowing a 3rd party to easily understand what was discussed and what decision/s the client took. 

How to ensure completeness and accuracy of contact notes:

  • If the BR/ZR has several order givers please use initials to allow for proper identification.

  • For any buy trade placed, you need to specify the solicitation context (actively solicited, reverse solicited, unsolicited) → reference is made to "Determine Solicitation Type".
    Your comment must cover the following: 
    • Who came up with the investment idea;
    • How was the decision made to trade this particular financial instrument(s);
    • You need to explicitly confirm whether advice was provided or not. If multiple instruments are discussed in the same advisory session, please specify for each individual instrument, whether advice was provided or not.

  • Providing the full picture: If the client submits orders via e-mail and you call back the client to provide warnings. You can choose in the CCN in WN at the end of the Session e.g. "E-mail" as channel, but then it is important to mention in the free text that also a call with the client took place to provide the warnings, otherwise any third party will only understand that an e-mail has been provided not any additional communication. Store all written evidence in the archiving system. 


  • Service Model Advice Light (former Advice Basic): Please remember that active solicitation is not allowed for this Service Model. Hence, you may only advice on a specific client request (client needs to mention 3 product attributes).   

  • Pay special attention when it comes to a K&E alert. It requires thorough documentation → reference is made to "Knowledge & Experience (K&E)"
    • For “I have warned” your documentation must include the following (Note: In WN, both points are automatically noted in the CCN after justifying):
      (i) With regards to which instrument class has the partner been warned?
      (ii) How has the partner been warned (channel: phone/mail/meeting, etc.)?

    • For “I will educate” your documentation must include the following (Note: In WN, if Edu Material is submitted vie e-channel and education confirmed, points (I-III) are automatically noted in the CCN but you need to add the confirmation point (iv):
      (i) You need to provide a confirmation that the respective education material has been provided
      (ii) Which instrument class has the partner been educated on?
      (iii) Through which channel has the partner been educated (channel: phone/mail/meeting, etc.)?
      (iv) You need to state that the partner confirmed to you to have understood the contents of the education material and that the client consented in having his/her knowledge in this particular instrument class to be permanently changed to “good”

    • For “I have considered” (MIFID only) your documentation must include the following (Note: In WN, points (i/ii) are automatically noted in the CCN after justifying, but you need to add the considerations point (iii) :
      (i) With regards to which instrument class did you inform the client about the missing experience?
      (ii) Through which channel has the partner been informed about it (channel: phone/mail/meeting, etc.)?
      (iii) Which considerations did you take into account to nevertheless advise on the trade (e.g. provided additional information about the risks of the instrument).

      In any case, if the client interaction happens by e-mail, please make sure the respective evidence is duly archived.

Note: Mixed sessions need to be suitable at all times. If the client instructs on a transaction, which triggers alerts and makes the initial advice unsuitable, the RM needs to advice against the transaction or amend the initial recommendation by changing the amount or switch into another instrument. 


*Important: If less then 3 criteria are mentioned, the advice is considered "unspecific client request" and must be marked as actively solicited. It is especially important to document the 3 criteria in the following situations:

  • Cross Border
  • Advice Light Service Model

Since in above mentioned scenarios active solicitation might / is not possible.
